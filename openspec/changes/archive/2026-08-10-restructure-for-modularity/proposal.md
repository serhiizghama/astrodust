# Перестройка модульных границ и снижение стоимости контекста

## Why

Проект находится в объёме MVP — ходьба, копание, сбор, цикл заработка, — и
собственно кода в нём немного: 4 491 строка без комментариев и пустых строк
на 38 файлов. Объём кода проблемой не является и сокращения не требует.

Проблемой стала **стоимость типичной задачи**: чтобы добавить механику, агенту
(и человеку, вернувшемуся к файлу через месяц) приходится прочитать несколько
тысяч строк, из которых больше трети — проектная проза об обоснованиях уже
принятых решений. Причины измеримы:

| Что | Цифра |
|---|---|
| `src/config.ts` — комментарии | **74 %** (424 из 571), импортируется почти всеми модулями |
| `src/world/materials.ts` — комментарии | **59 %** (414 из 696) |
| `src/world/simulation.ts` — комментарии | 38 % (346 из 893) |
| `tests/smoke.ts` | **7 407 строк одним файлом**, 496 проверок |
| `CLAUDE.md` | **отсутствует** — карта проекта строится заново каждую сессию |
| `openspec/config.yaml` → `context` | **пустой** — блок, который openspec показывает агенту, не заполнен |

К этому добавляются две структурные помехи:

- **Цикл `world/ ↔ entities/`.** `world/builder.ts` импортирует
  `entities/buildings`, `entities/catalog`, `entities/landing-module`;
  `world/vacuum.ts` — `entities/inventory`; `world/worlds/luna.ts` —
  `entities/landing-module`; при этом все `entities/*` импортируют
  `world/world`. Названия каталогов обещают слоистость, которой нет, и на
  вопрос «что нужно прочитать для этой задачи» нет ограниченного ответа.
- **`main.ts` — оркестратор на 495 строк с дублированием.** `step()` и
  `stepOverlay()` содержат скопированную последовательность обновления мира.
  Дублирование существует уже при двух состояниях; третье (пауза, смерть,
  экран запуска) даст третью копию, и копии разойдутся.

Отдельно: проза несёт настоящее знание, и часть его **не продублирована
в спеках**. Проверка показала, что инвариант порядка обновлений внутри шага
(`инструмент → игрок → симуляция → здания → модуль`) не покрыт ни спекой,
ни тестом — он существует только как абзац комментария в `main.ts`. Удалять
прозу можно лишь после того, как такое знание поднято в спецификации
или сжато в утверждение, остающееся в коде.

## What Changes

**Проза сжимается до утверждения, а не переносится.** Отдельного журнала решений
(`docs/decisions/`) не заводится: источник правды об обоснованиях —
`openspec/specs/`, и второе место для того же знания разошлось бы с первым.

- **Критерий вместо классификации.** Блок остаётся в коде, только если без него
  возможна **молчаливо неверная правка** — та, что скомпилируется и пройдёт
  тесты. Остаётся при этом не рассказ, а утверждение: инвариант, вывод числа,
  запрет или нелокальный эффект — одна-две строки со ссылкой на проверку,
  которая его держит. Всё остальное (пересказ кода, обоснование баланса
  на ощупь, история решений, риторика) удаляется. Разбор — в `design.md` → D8.
- **Спеки идут первыми.** Если сжатая формулировка оказывается требованием
  к поведению, а в спеках его нет — оно дописывается в спеку **до** удаления
  из кода. Вывод константы требованием к поведению не является и остаётся
  в коде.
- **Инвариант, который можно проверить, становится тестом, а не комментарием**
  — такой стоит ноль контекста: его не нужно читать, он падает сам.
- **Целевой ориентир по комментариям** — ~15 % строк файла против нынешних 41 %,
  с явным исключением для `simulation.ts`, где порядок правил невосстановим
  из кода. Ориентир — признак, что файл стоит пересмотреть, а не приёмочный
  критерий: решает критерий, а не процент.
- **`CLAUDE.md`** с картой проекта: куда идти за каждым видом изменения, какие
  инварианты не трогать, какие каталоги не читать без нужды
  (`openspec/changes/` — 1.4 МБ), критерий, по которому комментарий
  остаётся в коде.
- **`openspec/config.yaml` → `context`** заполняется: стек, конвенции, язык
  комментариев и спек, ключевые инварианты.
- **`tests/smoke.ts` разбивается по capability.** Секции внутри файла уже
  размечены и совпадают с именами спек один в один. Общая обвязка (`check`,
  фикстуры, фейковый ввод) выносится в `tests/harness.ts`; появляется запуск
  подмножества (`npm test -- conveyor`).
- **Тест на инвариант порядка шага.** Самое хрупкое место проекта защищено
  сейчас только прозой; после сжатия оно обязано быть защищено проверкой.
- **Явные публичные контракты подсистем.** Каждая подсистема получает
  небольшой файл с типами и публичной поверхностью, который можно прочитать
  вместо реализации.
- **Цикл `world/ ↔ entities/` разрывается.** `Builder`, `Vacuum`, `Digger`,
  `Painter` — это геймплейные сервисы, а не мир; они переезжают в отдельный
  слой. Таблица цветов материалов уходит из `world/materials.ts` в `render/`:
  доменная модель не должна зависеть от представления.
- **`main.ts` разгружается.** Расчёт контура постройки уходит в `Builder`;
  общий шаг мира выделяется в один модуль и перестаёт дублироваться между
  игрой и оверлеем; девять позиционных параметров `Renderer.render()`
  сворачиваются в кадровый снапшот.

**Не входит в объём:** изменение геймплея, добавление механик, сохранения,
вынос симуляции в worker/WASM, замена HUD-текста растровым шрифтом. Поведение
игры после этой работы обязано остаться наблюдаемо тем же.

## Capabilities

### New Capabilities

Нет. Работа не вводит нового наблюдаемого поведения.

### Modified Capabilities

- `game-shell`: добавляется требование о **порядке обновлений внутри шага
  симуляции**. Инвариант существует и соблюдается в коде уже сейчас, но нигде
  не записан: он живёт комментарием в `main.ts`, который эта работа сжимает.
  Нарушение порядка наблюдаемо (вещество засыпает персонажа изнутри, продукт
  машины засчитывается на кадр позже), поэтому это требование к поведению,
  а не деталь реализации.

Остальные пункты работы спек не меняют: перенос файлов, разбиение тестов,
сжатие комментариев и карта проекта наблюдаемого поведения не касаются,
а модальность оверлея, детерминированность порядка зданий и статус персонажа
как препятствия для сыпучего уже записаны в `research`, `building-placement`
и `material-simulation` соответственно.

## Impact

**Затрагиваемый код** — весь `src/**` (сжатие комментариев), с перемещением файлов:

- `src/world/{builder,vacuum,digging,painter}.ts` → новый слой геймплейных
  сервисов;
- таблица цветов из `src/world/materials.ts` → `src/render/`;
- `src/main.ts` — разгрузка, устранение дублирования `step`/`stepOverlay`;
- `src/render/renderer.ts` — сигнатура `render()`.

**Тесты** — `tests/smoke.ts` (7 407 строк) распадается на файлы по capability
плюс общая обвязка; `package.json` получает изменённый скрипт `test`.

**Документация и оснастка** — новый `CLAUDE.md`, заполненный `context`
в `openspec/config.yaml`, дописанные обоснования в затронутых спеках.

**Публичного API у проекта нет**, ломать нечего: все перемещения внутренние.
Внешне наблюдаемое поведение игры не меняется — это условие приёмки, а не
побочный эффект.

**Риск** — потеря знания при сжатии комментариев. Снимается тремя средствами:
блок остаётся, если без него возможна молчаливо неверная правка; дозапись
в спеки идёт **до** правки кода, а не после; проверяемые инварианты уезжают
в тесты, где их нельзя потерять молча. Работа ведётся по одному файлу
с прогоном своего набора после каждого.
