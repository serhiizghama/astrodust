# CLAUDE.md

Браузерная 2D пиксельная игра: космонавт садится на небесное тело, копает
полностью разрушаемый мир и перерабатывает породу в фабрику. Жанр — Noita ×
Factorio.

TypeScript + Vite, рендер в `<canvas>` через `ImageData`, звук — Web Audio.
**Ноль рантайм-зависимостей**, всё игровое написано руками. Код, комментарии,
спеки и общение — на русском.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер на :5173 |
| `npm run typecheck` | `tsc --noEmit`, строгий режим |
| `npm test` | проверки ядра в Node, без браузера |
| `npm run bench` | стоимость кадра рендера |
| `npm run shot` | скриншоты сцен через Playwright в `shots/` + числовые метрики |
| `npm run verify:audio` | офлайн-рендер звука и проверка сигнала |
| `npm run build` | typecheck + продакшн-сборка |
| `npm run format` | Prettier |

Готовым считается только то, что прошло `npm run typecheck` и `npm test`.

## Карта

Зависимости идут строго вниз по этой таблице. Ребро вверх — ошибка, её ловит
`tests/architecture.ts`.

```
src/
├─ main.ts          бутстрап, шаг игры, сборка снапшота для рендера
│
├─ core/            display (канвас, апскейл), input (снапшот ввода), loop (фикс. шаг)
├─ render/          renderer (пиксели в ImageData), camera, backdrop (небо),
│                   overlay (меню исследований), material-colors, sprites/
│
├─ systems/         геймплейные сервисы: digging, vacuum, builder, painter.
│                   Применяют действие игрока к миру — слой НАД миром и сущностями
│
├─ entities/        player, inventory, buildings (реестр + база), separator,
│                   conveyor, catalog (что можно строить), landing-module
├─ progress/        research (очки и покупки), technologies (таблица), tuning (профиль)
│
├─ world/           world (Uint8Array ячеек), materials (таблица веществ),
│                   simulation (клеточный автомат), chunks (грязные области),
│                   reactions, rng, worlds/luna (генератор мира).
│                   Ничего не знает о сущностях, прогрессе и рендере
│
├─ audio/           soundscape (шина), context, model, signals, voice, voices/*
│
└─ листы, не зависящие ни от чего:
   ├─ config.ts     ВСЕ настраиваемые константы. Числа менять только здесь
   ├─ palette.ts    RAMP — все цвета игры
   └─ geometry.ts   Rect — прямоугольник в ячейках
```

У каждой подсистемы есть `index.ts` — её публичная поверхность и **единственный
вход извне**. Чтобы узнать, что подсистема предлагает, читается он, а не её
файлы.

Спеки — `openspec/specs/<capability>/spec.md`, по одной на способность.
**Спека — источник правды о поведении и о том, почему оно такое.**
Проверки — `tests/<capability>.ts`, имена совпадают со спеками один в один.

## Куда идти за изменением

| Задача | Куда |
|---|---|
| Новое вещество | строка в `world/materials.ts`. Поведение выбирается по `state` и `density`, автомат править **не нужно** |
| Новое поведение вещества (нет подходящего `state`) | `world/simulation.ts` — только тогда |
| Новая постройка | `entities/catalog.ts` + описание вида; машина с состоянием — свой класс от `Building`, постройка без состояния — `sectionKind()` |
| Новая технология | `progress/technologies.ts`. Эффект — данные (`unlock` или `param`), **не ветка кода** |
| Любое число (скорость, цена, радиус, цвет неба) | `config.ts` |
| Новый цвет | `palette.ts` → `RAMP`. Цветов вне `RAMP` в игре нет |
| Новая клавиша | `core/input.ts` + `game-shell` спека (полное управление с клавиатуры — требование) |
| Новый мир | `world/worlds/<name>.ts` + `WorldProfile`. Гравитация и палитра — свойства мира, не константы |

## Инварианты — не трогать

**Порядок обновлений в шаге.** `main.ts` → `step()`:

```
переключатели → инструменты (копание, сбор, стройка, высыпание)
  → персонаж → клеточный автомат → машины → приёмник
  → камера → отчёт для звука → input.endStep()
```

Каждое сочленение наблюдаемо. Инструменты до персонажа и персонаж до автомата —
иначе вещество засыпает персонажа изнутри. Машины и приёмник после автомата и
в этом порядке — иначе продукт засчитывается на шаг позже. Отчёт для звука
после автомата и до `endStep()` — иначе он описывает предыдущий шаг или теряет
разовые нажатия.

**Детерминированность.** В симуляции нет и не может быть `Math.random()`:
вариативность берётся из номера шага через `world/rng.ts`. Иначе поведение мира
невоспроизводимо и непроверяемо.

**Фиксированный шаг.** Симуляция идёт 60 раз в секунду независимо от частоты
кадров. Число догоняющих шагов за кадр ограничено сверху.

**Один источник правды о геометрии.** Мир — `Uint8Array` ячеек. По нему же
считается коллизия и строится картинка. Второго (тайлмапа, списка спрайтов,
слоя коллизий) заводить нельзя.

**`blocksPlayer` и правила движения вещества — разные вещи.** Сквозь воду
персонаж проваливается, но песок в ней тонет, а не проходит насквозь.

## Правила работы

**Комментарии — не более ~20 % строк файла** (`world/simulation.ts` — ~30 %,
там порядок правил автомата из кода невосстановим). В коде остаётся:

- контракт: что делает, что принимает, какой инвариант держит;
- обоснование **реализации**: почему такой алгоритм, раскладка памяти, разрез
  цикла.

В код **не** пишется обоснование **поведения** — почему игра ведёт себя так,
а не иначе. Это идёт в `openspec/specs/`. Два места для одной правды однажды
разойдутся.

**Импорт из чужой подсистемы — только через её `index.ts`.** Внутри подсистемы
файлы импортируют друг друга напрямую. Глубокий импорт снаружи
(`from '../world/materials'`) запрещён и валит `tests/architecture.ts`.
Новое публичное имя — это строка в `index.ts`; не перечисленное там не публично.

**`openspec/changes/` не читать без прямой необходимости** — 1.4 МБ архива
прошлых изменений. Нужно поведение — открывай `openspec/specs/`.

**Проверять, а не предполагать.** Не сообщать о готовности, пока `typecheck` и
`test` не прогнаны. Если проверка не запускалась — сказать об этом прямо.

**Прогресс ведётся через OpenSpec.** Новая работа — `/opsx:propose`, реализация
— `/opsx:apply`. Спеки правятся вместе с поведением, а не после него.
