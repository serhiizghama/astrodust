# 01 — Стек и архитектура

## Решение

**Vite + TypeScript + Canvas2D. Без игрового движка.**

Ноль рантайм-зависимостей. Всё, что есть в проде — наш собственный код.

## Почему так

Вся игра — это один буфер пикселей. Мир хранится в `Uint8Array` (id материала на
каждый пиксель), рисуется через `ImageData` → `putImageData` на маленький канвас
(480×270) и растягивается CSS'ом с `image-rendering: pixelated`.

Это и есть пиксель-арт: не «стилизация под пиксели», а честные пиксели.

### Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| **Phaser 3** | Заточен под спрайты и тайлмапы. Клеточный автомат будем делать *вопреки* движку. ~1 МБ ради того, что нам не нужно. |
| **PixiJS** | Хороший WebGL-рендерер, но батчить нечего — у нас одна фуллскрин-текстура. Разумный апгрейд позже, оверкилл сейчас. |
| **WebGL напрямую** | Правильно для больших миров, но у клеточного автомата на GPU проблемы с порядком обновления. Не на первом шаге. |
| **Rust + WASM** | Честный ответ для производительности симуляции. Тяжёлый старт. Оставляем как путь миграции. |

### Путь миграции

Игровая логика не знает, чем её рисуют. Когда упрёмся в производительность:
- меняем слой блиттинга Canvas2D → WebGL, или
- переносим только симуляцию в Rust/WASM (мир уже плоский `Uint8Array` — он
  передаётся в WASM без копирования).

Игровой код при этом не трогаем. Ради этого и держим слои раздельно.

## Ключевое архитектурное решение

**Мир — это не тайлмап. Мир — это массив пикселей. Коллизия — по пикселям.**

```
Обычный платформер                  ASTRODUST
┌────┬────┬────┐                    ░░░░░░▓▓▓▓░░░░
│tile│tile│tile│  тайлы 16×16       ░░▓▓▓▓▓▓▓▓▓▓░░   каждый пиксель = ячейка
├────┼────┼────┤  коллизия по       ▓▓▒▒░░░░▒▒▓▓▓▓   коллизия по пикселям
│tile│    │tile│  сетке тайлов      ▓▒▒░░@░░░▒▒▒▓▓   разрушаемость бесплатно
└────┴────┴────┘                    ▓▓▒▒░░░░░▒▒▓▓▓   песок подключается сам
```

Принять это надо **сейчас**. Если сделать тайлмап ради «быстрого первого шага»,
то на шаге с песком придётся переписать движение, камеру и рендер целиком.

## Структура проекта

```
astrodust/
├─ index.html
├─ package.json
├─ tsconfig.json
├─ vite.config.ts
├─ docs/
└─ src/
   ├─ main.ts              # бутстрап + игровой цикл
   ├─ config.ts            # ВСЕ константы в одном месте (тюним отсюда)
   ├─ palette.ts           # RAMP — все цвета игры
   ├─ geometry.ts          # Rect
   ├─ core/
   │  ├─ loop.ts           # fixed timestep
   │  ├─ input.ts          # клавиатура + мышь → снапшот состояния
   │  └─ index.ts          # публичная поверхность подсистемы
   ├─ world/
   │  ├─ materials.ts      # таблица материалов: id, цвет, solid, density
   │  ├─ world.ts          # Uint8Array сетка: get / set / isSolid
   │  ├─ simulation.ts     # клеточный автомат веществ
   │  └─ worlds/
   │     └─ luna.ts        # генерация первого мира + его гравитация и палитра
   ├─ systems/             # копание, сбор, стройка, отладочная установка
   ├─ entities/
   │  └─ player.ts         # состояние и контроллер (спрайт — в render/sprites)
   ├─ progress/            # исследования, технологии, профиль настроек
   └─ render/
      ├─ camera.ts         # follow + deadzone + кламп к границам
      ├─ renderer.ts       # world → ImageData → канвас → апскейл
      └─ sprites/          # как выглядят сущности
```

Зависимости идут строго вниз: `main → core/render → systems →
entities/progress → world → листы`. У каждой подсистемы есть `index.ts` —
её публичная поверхность и единственный вход извне; глубокий импорт снаружи
запрещён и проверяется `tests/architecture.ts`.

Единственный источник правды о мире — `world.cells`. Игрок его читает
(коллизия), позже будет и писать (копание).

## Цифры

| Параметр | Значение | Комментарий |
|---|---|---|
| Внутреннее разрешение | 480×270 | 16:9, апскейл целым множителем (×2/×3/×4) под окно |
| Размер мира (MVP) | 1024×512 пикселей | помещается в память с запасом, камера скроллит |
| Частота симуляции | 60 Гц, фиксированный шаг | детерминизм; рендер отдельно через rAF |
| Формат ячейки | `Uint8Array`, 1 байт | до 256 материалов — хватит надолго |

## Инструменты

- **Vite** — дев-сервер с HMR, ноль конфига, продакшн-билд из коробки
- **TypeScript** — strict mode
- **Prettier** — форматирование
- Тесты: пока нет. Появятся вместе с симуляцией материалов, где логика
  становится нетривиальной и её реально нужно проверять.
